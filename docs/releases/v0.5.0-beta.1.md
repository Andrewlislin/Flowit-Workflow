# Flowit Workflow v0.5.0-beta.1

`v0.5.0-beta.1` is the first productization beta of Flowit Workflow. It moves the project from a host-neutral orchestration core with manual integrations to an installable multi-host workflow product layer.

## Highlights

### One setup lifecycle across Agent hosts

The CLI now provides the same lifecycle surface across built-in hosts:

```bash
flowit-workflow setup <host> --dry-run
flowit-workflow setup <host>
flowit-workflow doctor <host>
flowit-workflow repair <host>
flowit-workflow uninstall <host>
```

Implemented providers:

- WorkBuddy — MCP + Bridge Worker Skill + Hooks + durable Bridge transport;
- Claude Code — isolated skills-directory plugin with Skills, Hooks, and MCP;
- Codex — conservative `config.toml` MCP integration;
- OpenCode V2 — comment-preserving JSONC `mcp.servers` integration;
- DeepSeek Harness — native Cordis plugin/patch integration;
- 豆包办公 — guided Bridge Worker staging with explicit host-side manual steps.

Every provider is dry-run capable, idempotent, ownership-aware, and fail-closed on conflicting user configuration.

### Built-in workflow presets

Three reusable product templates are included:

- `content-studio` — Radar → Topic Strategist → Researcher → Writer → Fact Checker → Chief Editor;
- `research-lab` — Research Planner → Researcher → Skeptic → Synthesizer → Research Reviewer;
- `agent-team` — Planner → Researcher → Executor → Reviewer.

Presets bind abstract roles to real Agent Sessions and create durable Flowit Pipelines. A single Session can own every role, or roles can be split across Sessions and supported hosts.

```bash
flowit-workflow preset list
flowit-workflow preset show content-studio
flowit-workflow preset install content-studio \
  --adapter=workbuddy \
  --session=all=<session-id> \
  --input="AI engineering" \
  --dry-run
```

### Durable preset activation

Preset installation remains manual by default. Users can explicitly opt into durable activation:

```bash
# Daily at 08:00 local Shanghai time
flowit-workflow preset install content-studio \
  --adapter=workbuddy \
  --session=all=<session-id> \
  --schedule=daily \
  --time=08:00 \
  --timezone=Asia/Shanghai \
  --yes

# Monday-Friday
--schedule=weekdays --time=08:00 --timezone=Asia/Shanghai

# Fixed interval
--schedule=every --every-seconds=3600
```

Schedules can target Pipelines directly. Scheduled Pipeline execution uses stable occurrence identities and preserves Flowit's at-least-once recovery and deduplication semantics across multiple workers. Calendar schedules use IANA time zones; nonexistent local times during DST spring-forward are skipped rather than silently shifted.

## Safety boundaries

- Flowit remains **at-least-once**, not universally exactly-once.
- External side effects without host-native idempotency or transactions can still repeat after failures.
- Preset installation never executes Agent work immediately.
- `content-studio` deliberately stops at a human-reviewable final artifact and does not auto-publish.
- Host authentication, permission systems, sandboxing, workspace trust, and approval gates remain authoritative.
- WorkBuddy Desktop and 豆包办公 still require host-native unattended Automation configuration where the host exposes no safe public mutation API.

## Beta installation

After npm publication completes:

```bash
npx @coaseedge/flowit-workflow@beta setup
```

Or install explicitly:

```bash
npm install -g @coaseedge/flowit-workflow@beta
flowit-workflow setup
```

Node.js requirements: `^22.19.0` or `>=24.0.0`.

## Validation

The release gate requires the repository's full CI chain plus release-specific artifact validation:

- registry-only dependency sources;
- frozen pnpm lockfile;
- package-boundary checks;
- build and strict TypeScript validation;
- package tarball smoke tests;
- exact prerelease version parity across all packages and host metadata;
- exact internal dependency versions in packed manifests;
- Unit/Recovery and Host contract tests;
- required CLI/setup/preset/Bridge assets present in the root tarball.

This is a prerelease. Host integrations marked Experimental/Pilot should continue to be treated conservatively until broader real-host beta validation is complete.
