# Flowit Workflow v0.5.0-beta.4

`v0.5.0-beta.4` closes the installation-to-execution gaps found in real Claude
Code and Codex conversations after `v0.5.0-beta.3`. It keeps Claude's trusted
adaptive-routing authority isolated while adding a safe, explicit Codex path for
clean, durable, permission-bounded run-once workflows.

## Highlights

- Adds the bilingual **Build with Flowit** Creator entry, Quickstart, Studio SDK,
  Package Spec, installation, publishing, Starter Example, and Community Studio
  navigation without turning the root README into SDK reference material.
- Makes the adaptive MCP surface Host-aware: Claude Code retains the trusted
  `workflow_assess → workflow_prepare → workflow_commit` chain, while other
  Hosts receive advisory assessment without impossible Claude caller tokens.
- Scopes Codex output to the exact completed Turn and omits an unprovable
  summary instead of exposing an entire historical Thread.
- Adds `run_once_start` and `run_once_get` for explicit Codex workflows in a
  newly provisioned dedicated Session, with strong `requestId` idempotency,
  durable provisioning intent, restart recovery, and uncertain-outcome fencing.
- Adds bounded Codex execution envelopes for `workspace-read`,
  `workspace-write`, and `network`. Sensitive capability requests require MCP
  elicitation, then become signed, expiring, run-scoped execution grants.
- Enforces approved working-directory, Sandbox, network, writable-root, model,
  and reasoning constraints across preflight, Thread lifecycle, every Turn,
  fresh admission, and journaled recovery.
- Preserves immediate exact-model reroute interruption and rejects permission
  drift before replacement-model work can complete.
- Pins the supported Codex App Server v0.152.0 lifecycle/Turn Schema contract;
  read-only network workflows use a no-broader-than-approved offline Thread
  bootstrap and the exact approved `sandboxPolicy` on every `turn/start`.

## Install

Run setup directly from npm:

```bash
npx @coaseedgeltd/flowit-workflow@beta setup
```

Or install the compatibility distribution globally:

```bash
npm install -g @coaseedgeltd/flowit-workflow@beta
```

The Studio Creator CLI remains included:

```bash
npx --package @coaseedgeltd/flowit-workflow@beta flowit-studio --help
```

## Security and compatibility boundaries

- Codex permission envelopes do not grant Browser/Computer Use,
  `danger-full-access`, administrator privileges, arbitrary writable roots,
  cross-Adapter authority, or external publishing authority.
- Codex explicit run-once is a Host-approved mutation, not a substitute for
  Claude Code's trusted current-Turn authority channel.
- Read-only Thread bootstrap may be narrower than an approved online Turn, but
  it may never be broader; every work-producing Turn receives the exact approved
  structured Sandbox policy.
- Existing Host authentication, workspace trust, MCP approval, sandbox, and
  external-side-effect confirmation remain Host-authoritative.

## Release integrity

The release workflow validates the full workspace, packs the exact nine npm
artifacts, verifies names, versions, dependency pins and required files,
generates `SHA256SUMS`, creates a GitHub prerelease, and publishes the same
artifacts to npm with provenance. The `beta` and `latest` dist-tags are both
synchronized to this version by the reviewed workflow.
